# ADR-0017：Stage 1 Base 的全局batch 与即时执行

- 状态：已接受
- 日期：2026-08-13
- 局部取代：ADR-0013/0015 中全局batch 256 与默认 `compile: true` 的决定

## 决定

Stage 1 正式 Base 的全局batch 固定为 128，梯度累积为 1。单卡每步处理 128 条；DDP 按 rank 平分该全局batch，因此全局batch 必须能被 world size 整除。轮仍按自然频率完整覆盖训练集，优化器步数、预热和余弦时钟由实际行数与全局batch 128 推导。

正式 Base 默认 `training.compile: false`，直接使用即时执行。`compile` 继续写入运行配置、检查点和元数据，但不进入科研实验身份；恢复时允许显式切换。若将其设为 `true`，编译异常仍必须直接终止，不得静默回退即时。

ADR-0013/0015 中其他模型、数据、loss、优化器、验证、检查点 v2 和第边界恢复合同保持不变。

## 理由

正式 YAML 和已启动运行均已使用全局batch 128 与即时执行。将这两项明确为现役合同，可消除配置、测试、运行指南和恢复认知的分叉，且不扩张到 Stage 1 其他科研决定。

## 后果

相同轮现在包含更多优化器步，不应将全局batch 128 训练与旧全局batch 256 训练视为可直接继续的同一运行。Stage 1 检查点 kind 和 `format_version=2` 不变；检查点中的完整配置、配置 hash、每轮步数与恢复校验会阻止错误混接。Stage 2 仍只消费完成的 Stage 1 v2 检查点。
